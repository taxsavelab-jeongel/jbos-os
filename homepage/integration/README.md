# 홈페이지 상담 신청 → 리드 자동화 연결 절차

> ## ⛔ 현재 미사용 — 실행하지 마십시오
>
> 정엘의 **모든 상담 신청 동선은 `lp.jeongellab.com` 한 곳으로 통일**되었습니다.
> 홈페이지에는 자체 신청 폼이 없고, 모든 CTA가 해당 랜딩페이지로 연결됩니다.
> 따라서 이 폴더의 절차는 **현재 쓰이지 않습니다.**
>
> `setupConsultForm()` 을 실행하면 구글폼과 마스터DB 탭이 새로 생성되므로,
> 아래 내용을 실행에 옮기기 전에 반드시 신청 동선을 다시 정하십시오.
>
> 남겨둔 이유: 나중에 홈페이지나 다른 페이지에 자체 폼을 붙이기로 결정할 경우
> 폼 생성·마스터DB 연결·확인 메일·트리거 설치 코드를 그대로 재사용할 수 있기 때문입니다.
> 코드 자체는 검증을 마친 상태입니다.

---

홈페이지의 상담 신청 폼을 기존 리드 파이프라인(마스터DB · 텔레그램 · 확인 메일)에 연결하는 절차입니다.
회사 표준 인프라(`jeongel-offer-deployment` 스킬)를 그대로 재사용하며, **새로 만드는 것은 구글폼 1개와
캠페인용 Apps Script 프로젝트 1개뿐**입니다.

## 동작 구조

```
홈페이지 상담 신청 폼 (custom UI)
        │  POST (no-cors)
        ▼
구글폼 formResponse 엔드포인트
        │
        ▼
마스터DB「홈페이지 상담신청」탭  ──┬─→ 공용 Apps Script  : 텔레그램 알림 + 원본백업
   (원본)정엘가업승계 인디비 종합   └─→ 캠페인 Apps Script: 신청자 확인 메일
```

브라우저에서 구글폼으로 **직접 제출**하기 때문에 실제 폼 제출과 동일하게 취급되어,
공용 프로젝트의 `onFormSubmit` 트리거(텔레그램·백업)가 그대로 동작합니다.
디자인은 홈페이지 것을 쓰고 배관만 기존 것을 재사용하는 구조입니다.

## STEP 1 — 캠페인 Apps Script 프로젝트 생성

1. https://script.google.com → **새 프로젝트**
2. 프로젝트 이름을 `정엘-홈페이지상담-캠페인` 으로 지정
3. `apps-script-campaign.gs` 의 내용을 **전부 붙여넣고 저장**

## STEP 2 — 폼 생성 (`setupConsultForm` 1회 실행)

함수 선택 → `setupConsultForm` → 실행 → 권한 승인.

> ⚠️ 권한 승인 직후 **직전에 대기 중이던 함수가 다시 실행**되는 경우가 있습니다.
> 그래서 `setupConsultForm()` 은 멱등하게 작성해 두었습니다 — 이미 폼이 있으면
> 새로 만들지 않고 기존 폼을 그대로 씁니다. 재실행되어도 폼이 중복 생성되지 않습니다.

실행 로그에서 확인할 것:

- `폼 생성 완료` 와 편집/공개 URL
- `응답 탭 이름을 "홈페이지 상담신청" 로 변경했습니다`
- **`════════ 아래 블록을 … LEAD_CONFIG 와 통째로 교체하십시오 ════════`** 로 시작하는 블록

## STEP 3 — 홈페이지에 LEAD_CONFIG 반영

STEP 2 로그에 출력된 블록을 `homepage/assets/site.js` 의 `LEAD_CONFIG` 자리에 통째로 붙여넣습니다.
그 블록을 그대로 보내주시면 대신 반영해 드립니다.

`action` 이 비어 있는 동안에는 폼이 **메일 작성 창을 여는 방식으로 자동 대체 동작**합니다.
연동 전에도 사이트는 정상적으로 쓸 수 있으며, 값이 채워지는 순간 자동 전송으로 바뀝니다.

## STEP 4 — 공용 프로젝트에 2줄 추가

공용 Apps Script(`1UHWHl-yf…`)의 `Code.gs` 에서 **두 블록 모두** 한 줄씩 추가합니다.
한쪽만 넣으면 텔레그램이 오지 않거나 백업이 남지 않습니다.

```js
// ① 텔레그램 알림
var SHEET_NOTICE_CONFIG = {
  ...
  '홈페이지 상담신청': { label: '홈페이지 상담 신청 접수', title: '홈페이지 상담 신청' }
};

// ② 원본 백업 (백업 시트는 코드가 자동 생성)
var RAW_BACKUP_SHEETS = {
  ...
  '홈페이지 상담신청': '홈페이지 상담신청_원본백업'
};
```

> 앵커를 잡을 때 `'가지급금 손실 계산기'` 는 **양쪽 블록에 모두 존재**합니다.
> 어느 블록에 넣고 있는지 반드시 확인하고 저장하십시오.

## STEP 5 — 메일 단독 검증

캠페인 프로젝트에서 `diagTestConsultMail` 실행 → 실행 로그 `완료됨` + 본인 Gmail 수신 확인.
트리거를 걸기 전에 메일 로직만 먼저 검증하는 단계입니다.

## STEP 6 — 트리거 설치

`installConsultTrigger` 실행.

standalone 프로젝트는 트리거 UI에 「스프레드시트에서」 항목이 나오지 않으므로 **코드로 설치**합니다.
같은 마스터DB에 공용 프로젝트 트리거와 캠페인 프로젝트 트리거가 동시에 걸리며, 각자 독립 실행되는 것이 정상입니다.

## STEP 7 — 라이브 엔드투엔드 테스트 (생략 불가)

배포된 홈페이지에서 회사명·성함에 `[테스트]` 를 붙여 실제로 제출한 뒤 **4가지 전부** 확인합니다.

- [ ] 마스터DB `홈페이지 상담신청` 탭에 행 추가
- [ ] 신청자 이메일로 확인 메일 도착 (본문까지)
- [ ] 캠페인 프로젝트 실행 로그 `완료됨`
- [ ] **텔레그램 알림 수신** — 이 항목은 대표님만 확인 가능합니다

## STEP 8 — 테스트 데이터 정리

`홈페이지 상담신청` 탭과 `홈페이지 상담신청_원본백업` 탭 **양쪽**에서 테스트 행을 삭제합니다.

## 알려진 사항

- **발신 주소**: Apps Script를 실행한 구글 계정으로 발송됩니다. 표시 이름은
  `정엘기업연구소 정선의` 로 나오지만 주소는 실행 계정 주소입니다.
  회사 주소로 바꾸려면 Gmail 「다른 주소에서 메일 보내기」 등록 후
  `MailApp.sendEmail({from: ...})` 지정이 필요합니다.
- **no-cors 전송**: 구글폼은 CORS 응답을 주지 않으므로 브라우저가 성공/실패를 읽을 수 없습니다.
  홈페이지는 전송 요청이 나간 시점에 완료 화면을 보여줍니다. 실제 수신 여부는 STEP 7로 검증합니다.
- **스팸 차단**: 폼에 허니팟 필드(`website`)를 두어 봇 제출을 걸러냅니다.
  사용자에게는 보이지 않으며, 값이 채워져 있으면 조용히 무시합니다.
